# 幕灯 · AI 辅助 TRPG 主持台

> Mudeng — LLM-Assisted TRPG Host Console

**幕灯**是一张给 AI 主持人和玩家共用的跑团桌：幕布后面是模组、NPC 和秘密，幕布前面是角色、骰子和故事。

一个本地优先的 TRPG 工作台：原生 HTML/CSS/JS 前端 + FastAPI/SQLite 后端。
目标是把大语言模型接成主持人的辅助工具，让主持人把精力放在关键判断上；
叙述、NPC 反应、判定请求、状态结算和节奏推进由 AI 提议，主持人保留最终确认权。

## 项目状态

> **持续开发中。**  
> 目前基本功能已经跑通，可以创建角色、开团、联机、保存进度和进行 AI 辅助主持；  
> 但界面细节、交互流程、稳定性和兼容性仍然比较粗糙，后续版本会有调整和不兼容变更。  
> 欢迎试用和反馈，不建议把它当作已经完成的生产级 VTT。


## 怎么打开

最简单的方式：双击桌面上的「跑团主持台」快捷方式，或项目里的 `启动跑团.bat`。

多人联机：双击 `启动联机.bat`，用同一 Wi-Fi / Tailscale / ZeroTier 下的局域网地址访问。详细说明见 [MULTIPLAYER.md](MULTIPLAYER.md)。

启动器会：

- 如果服务已经在运行，直接打开对应地址，不会重复启动
- 8000 被别的程序占用时，自动改用 8001–8010 里的空闲端口
- 首次运行自动创建 `.venv` 并安装依赖
- 打开一个服务窗口并自动打开浏览器；关闭服务窗口即停止

也可以手动启动（固定 8000）：

```powershell
.\start_server.ps1
```

或双击 `start_server.bat`。首次运行会自动创建 `.venv` 并安装依赖。然后打开：

```text
http://localhost:8000/
```

如果 8000 被占用，优先用桌面快捷方式，它会自动换端口并打开正确地址。

局域网多人时：

```powershell
.\start_server.ps1 -Lan
```

此时 AI 代理也会暴露在局域网中，请只在可信网络使用。

只想看界面、不用 AI 时，也可以直接双击 `index.html`；
但浏览器直连模型接口通常会被 CORS 拦截，所以 AI 主持建议始终走本地后端。

## AI 主持配置

API Key 只保存在服务端 `ai_config.json`，不会进入浏览器、存档或房间状态。
长团记忆：每 8 条公开消息自动生成阶段摘要；导演面板可手动生成摘要、发布前情提要、维护未解剧情线；NPC 支持“知道 / 不知道”知识边界，避免 AI 让 NPC 全知。玩家端不会收到 NPC 的秘密或知识边界字段。
也可以直接用环境变量覆盖：

```powershell
$env:TRPG_AI_API_KEY = "sk-..."
$env:TRPG_AI_MODEL = "deepseek-flash"
$env:TRPG_AI_ENDPOINT = "https://api.deepseek.com"
.\start_server.ps1
```

如果本机必须走代理才能访问模型接口，额外设置：

```powershell
$env:TRPG_AI_PROXY = "http://127.0.0.1:7897"
```

在界面里打开「设置 > AI 接口设置」可以修改接口、模型、温度和主持指令，
并点「测试连接」确认链路。默认配置为 DeepSeek：

- 接口：`https://api.deepseek.com`
- 模型：`deepseek-flash`（响应约 3–7 秒）
- 可选：`deepseek-v4-pro`（质量更高，但单回合可能需要 20–40 秒）

`ai_config.json` 已在 `.gitignore` 中，不会被提交。

不确定链路是否正常时，可以运行：

```powershell
.\.venv\Scripts\python.exe scripts\check_ai.py
```

它会依次检查 `/api/health`、密钥是否已配置，并让模型返回一个最小 JSON。

## 现在能做什么

### 战役与内容

- 管理战役、章节、局内时间、当前焦点和局势压力
- 编辑当前场景、地点、气氛、主线片段和不可改写设定
- 保存场景快照，方便回顾关键节点
- 自定义骰面、判定方式、大成功、大失败、默认修正和技能列表
- 支持“低于等于目标成功”和“高于等于目标成功”
- 管理玩家角色、血量、技能点、压力、状态、物品和技能
- 角色卡支持可选属性（力量 / 敏捷 / 意志等，每行“名称: 数值”）
- 判定遇到角色卡没有的技能不会卡住：先按最接近的技能（力量→格斗/运动/攀爬，敏捷→闪避/潜行/运动等）计算，再退到基础值（d100 为 30，d20 为 10）
- 管理 NPC 的性格、说话方式、目标、关系和秘密
- 管理线索卡和任务卡，并一键标记为已发现或发布给玩家
- 剧情节点、调查板、战斗格子地图、回合顺序和行动点
- 地图支持行动范围高亮、墙体 / 水域阻挡、困难地形、掩体、隐藏陷阱和随机地图
- 地图背景支持导入 PNG/JPG/WebP/GIF，主持人可缩放、平移、贴合格子并随地图发布给玩家
- 敌人回合自动行动：向最近玩家移动、进入武器范围后攻击、消耗移动/决策点并自动推进回合，可在回合面板开关
- 模组导入：TXT、Markdown、JSON、DOCX、PDF；按 8000 字分段，单段输出被截断时自动再拆分，解析时关闭模型思考以保证 JSON 完整
- 模组库章节的「进入本章」会切换当前场景并自动关闭模组库，避免看起来“点了没反应”
- 规则库、世界观库、角色库、模组库

### 视角与多人

- 主持人视角和玩家视角切换；玩家视角只显示公开内容
- 联网房间：房间码、设备身份、成员管理、行动请求、WebSocket 同步
- 玩家提交行动请求，主持人执行或驳回
- 导出 / 导入 JSON 存档，自动保存到浏览器 / 房间

### 战役档案与开局向导

- 首页「战役档案」列出当前进度和服务端存档，可直接继续或删除
- 「新建战役」打开三步向导：选模组 → 车卡 → 确认队伍和节奏
- AI 会阅读模组的章节、NPC 和线索，推荐角色概念、属性和技能分配
- 技能只能从当前规则和模组技能池里选，避免出现角色卡没有的“力量/敏捷”之类判定
- 技能分配点数默认 300，可逐项修改；技能点总数超限时不能进入下一步
- AI 推荐失败会自动使用本地兜底推荐，不阻塞开团
- 可以从角色库选已有角色，也可以新建；AI 队友从角色库里选，最多 2 个

### CoC 7e 完整车卡

- 九项属性：力量、体质、体型、敏捷、外貌、智力、意志、教育、幸运；支持 3D6×5 / (2D6+6)×5 掷骰
- 一次生成 5 组完整属性，玩家从 5 组里选一组；也可以直接手动修改
- 每项属性附带“按当前数值判断”的水平描述，例如 APP 10 会直接提示“远低于常人：如此难看……”，同时保留完整阈值参考面板
- 年龄修正：15–19、40–49、50–59、60–69、70–79、80+ 自动调整属性
- 衍生数值：生命、魔法、理智、移动、伤害加成、体格、闪避、母语
- 65 项技能基础值，区分职业技能和兴趣技能；职业点、兴趣点分别计算，创建上限 70
- 职业模板 21 个常用职业，另有「自定义职业」；职业决定职业技能、职业点公式和信用评级范围
- 背景：外貌、信念、重要之人、意义非凡之地、珍贵之物、特质、伤痕、恐惧症、神话典籍、背景故事
- 可从角色库「CoC 完整车卡」新建，或在编辑已有角色时点「编辑完整 CoC 卡」
- 角色卡支持最大化/还原，技能列表不再只能靠手动拉小滚动条
- 角色卡底部有固定「保存角色」栏，滚到任何位置都能保存
- 开局向导的「完整 CoC 车卡」按钮会把新角色回填到向导
- 技能/职业机械数据来源见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)

当前完整车卡是 21 个常用职业 + 自定义职业；还没有做全部扩展职业、武器表、经验包和自动职业点分配。

### D&D 5e 常用车卡

- 9 个 SRD 种族、12 个核心职业、13 个常用背景，中文名称
- 属性：4d6 去掉最低、标准数组、27 点点买或手动输入；种族加值自动叠加
- 等级 1–20：熟练加值、平均 HP、生命骰、AC（护甲 + 敏捷上限 + 盾）
- 技能：18 项技能，职业熟练选择 + 背景自动熟练；技能加值 = 属性调整 + 熟练
- 豁免：职业豁免熟练自动计算；先攻、速度、被动察觉、法术豁免 DC / 法术攻击
- 子职：每个核心职业一个 SRD 子职；法术位表覆盖完整施法者、半施法者和邪术师契约法术位
- 武器攻击：常用武器表，自动计算攻击加值和伤害
- 背景：性格、理想、羁绊、缺陷、背景故事；起始装备、金币、法术/戏法文本
- 可从角色库「D&D 5e 车卡」新建，或在编辑已有角色时点「编辑 D&D 卡」
- 开局向导里选择完整 D&D 卡后，会把规则切换为 d20 简化判定
- 开局向导第 3 步和主持台 AI 面板都支持「AI 按模组生成一个队友」；生成后自动加入角色库并选中
- D&D 判定支持 DC（默认 15）和优势/劣势；AI 可以给 checks 指定 dc 和 advantage

当前 D&D 车卡使用 SRD 数据，不含完整法术列表、专长和全部扩展子职；武器表是常用武器，不是完整装备目录。D&D 判定仍是 d20 + 技能调整 vs DC 的简化规则，还没有完整优劣势来源、对抗检定和法术效果自动化。

### 存档与恢复

- 本地状态保存在浏览器 localStorage；服务端自动存档和手动存档保存在 SQLite `campaign_saves`
- 主持台左侧工具栏集中开场、行动、AI、即时存档、地图、战斗、日志、聊天和资料入口
- AI 玩家与即时存档收进右侧抽屉，主区域只保留开场、行动、地图、战斗和聊天，减少纵向堆叠
- 视觉采用深蓝灯塔主题；游玩舞台是深色主舞台，管理面板保持浅色
- 玩家界面以聊天为主区域，场景、角色、地图、线索和调查板收进右侧上下文栏；技能判定默认折叠
- 即时存档写入服务端 `quick-1` 到 `quick-5`，重启服务或换浏览器后仍可读取
- 读档会覆盖当前进度，并保留存档中的 AI 设置
- 导入模组库同时保存到服务端 SQLite `module_library`，服务启动后按 ID 恢复到本地
- 换端口、清浏览器缓存或重启后，模组不会再丢失；旧版本已导入但还在 localStorage 里的模组，会在启动时自动补传到服务端
- 模组接口：`GET /api/modules`、`PUT /api/modules/{id}`、`DELETE /api/modules/{id}`
- 模组库支持单个模组预览、编辑 JSON、单独删除；不会因为删一个而清空全部
- 模组解析 2.0：按文本哈希缓存解析结果，同一文件再次导入不重复消耗 token；支持强制重解析
- 模组预览显示解析覆盖信息：输入字数、分段数、章节、场景、线索、NPC，以及缓存命中状态
- 模组编辑器支持可视化增删改章节、场景和线索：场景可改公开描述/主持秘密/线索/触发；线索可改类型、状态、来源和公开状态
- 章节和场景支持上下移动；完整 JSON 收在高级折叠区
- 手动修改后的模组会回写解析缓存，重新导入同一文件时保留修改
- 主持台新增「导演」抽屉：更新焦点/时间、发布公开叙述、记录秘密、发布线索、添加 NPC、调整玩家生命与状态
- 模组导入支持 TXT、Markdown、JSON、DOCX、PDF；可直接选择文件并交给 AI，不需要先把全文放进文本框
- 普通读取会显示提取字数和预计分段数；扫描版 PDF 会明确提示无法提取文字
- 模组导入降温到 0.15，并要求线索按原文保留，减少同一文本多次解析的线索数量波动；AI 抽取仍有随机性，不能保证每次完全一致

- 服务端存档：自动存档 + 手动存档，保存在本机 `trpg.sqlite3`，换端口、换浏览器或重开设备后可恢复
- 顶栏「存档」或设置菜单「存档管理」：命名保存、读取、删除，最多保留 50 个手动存档
- 自动存档每 10 秒最多写一次，关闭页面前会尝试再保存一次
- 新浏览器没有本地存档时，会自动读取最近一次自动存档
- 浏览器 `localStorage` 仍作为第一层缓存；换端口（8000 → 8001）或换 `localhost` / `127.0.0.1` 会变成不同来源，服务端存档不受影响
- 存档保存在本机服务端；用 `-Lan` 暴露到局域网时，能访问该地址的人也能读取存档，请只在可信网络使用

### AI 主持

- 「AI 主持本回合」：生成结构化回合（公开叙述、主持备注、判定请求、状态更新、下一步选择、场景推进、长期记忆）
- 「AI 公开叙述」「AI 判定建议」「AI 剧情节点」：单次生成工具
- 托管队列，三种模式：
  - **辅助**：只生成建议
  - **确认**：生成后等主持人确认
  - **全自动**：直接发布叙述并执行安全更新
- 「开启全自动托管」一键进入全自动模式
- 玩家发言 / 行动请求会自动进入队列，AI 按顺序处理
- 需要玩家投骰时，生成「待玩家判定」，主持人面板和玩家界面都会出现「填入投骰」按钮
- 玩家完成判定后，结果会自动回传给 AI，AI 继续叙述后果，不需要再点一次
- 一轮里有多个判定时，等所有玩家都投完再统一推进
- 也可以在没有任何玩家输入时点「AI 接手下一步」，让 AI 主动推进场面
- 「允许结算玩家数值」打开后，AI 可以结算 NPC / 环境对玩家造成的 HP、压力与状态变化
- 失败自动重试、错误自动暂停、刷新页面后自动恢复未完成的队列
- 当前生成可以「取消当前」；失败后可一键重试，玩家行动不会丢
- 回复长度支持短 / 标准 / 详细，短模式适合快速推进，详细模式适合氛围场景
- 玩家行动请求会显示等待时间；超过 30 秒变黄，超过 90 秒变红提醒主持人
- 长期记忆分三层：事实、阶段摘要、最近对话；每回合按相关度选取，不再整块塞入
- 模组原文自动分块，按当前行动做关键词检索，把最相关的几段注入 prompt
- 结构化输出校验：字段类型、目标是否存在、判定角色是否为玩家；结构错误自动修复一次，语义错误直接跳过并记录
- 流式叙述：主持的 `publicText` 边生成边显示，思考阶段显示已思考字数；流式失败会自动回退普通请求
- 聊天等待气泡：AI 主持生成期间在聊天流显示「等待主持人回复中…」
- 重新生成：对最近一条 AI 公开叙述可以要求重写（可填修改方向），并支持恢复上一版；只改文风，不重掷判定、不改状态
- 「AI 回合记录」面板：查看最近 20 回合的 prompt、原始返回、校验错误、token、延迟，可复制或重放
- 待判定面板支持「代骰」（主持人为玩家代掷，方便测试和单人主持）
- 导出跑团记录为 Markdown（聊天、判定、日志、长期记忆）

### AI 玩家（MVP）

- 最多选择 2 个玩家角色，让 AI 轮流扮演它们行动
- **默认跟随真人节奏**：AI 等真人玩家发言后再回应；每次真人行动后每个 AI 角色行动一次，然后回到等待，不会连续抢回合
- 取消「等待真人行动后再回应」后，才会连续跑 1–50 轮
- 可为每个角色单独设置「AI 人设」和「AI 目标」；留空时回退到角色卡的定位/备注和当前目标
- **信息隔离**：每个 AI 角色只看自己的角色卡、公开场景、公开聊天、已发布线索和 GM 给出的可选行动，不读取主持备注、NPC 秘密、隐藏线索或模组原文，也看不到另一个角色的人设设置
- AI 从 GM 的 `choices` 里选行动，也可以提出自己的合理行动
- GM 要求任一 AI 角色投骰时，平台自动投骰并把结果回传，不需要人工点
- 判定数值只写入日志，公开聊天只出现叙述，避免“主持辅助：骰 19/目标 70”这类词
- 支持暂停、停止、恢复和「AI 走一步」
- 回合历史会记录每个角色各自的行动和理由

当前 MVP 最多 2 个 AI 玩家；如果真人角色的待处理判定出现，AI 玩家会等待真人处理完再继续。

## 质量检查

```powershell
# 后端 + 密钥 + 模型连通性
.\.venv\Scripts\python.exe scripts\check_ai.py

# 8 个固定场景的 AI 主持回归测试（需要先启动后端）
node scripts\regression_ai.mjs
```

回归脚本会启动临时无头 Chrome，加载真实页面和真实 prompt，检查：
JSON 结构、是否替玩家做决定、判定角色是否存在、状态目标是否存在、模组原文是否命中。

## 当前限制

- AI 玩家 MVP 最多 2 个角色，默认等真人发言后再回应；如果所有角色都在 AI 队伍里，需要取消“等待真人”或增加真人角色
- 开局向导目前只读取模组库里的模组；内置模组仍走原来的“创建一个世界”表单
- AI 车卡只看模组的公开简介、章节、NPC 和线索，不读取 NPC 秘密；推荐失败会退回本地模板
- 公开叙述用提示词 + 正则过滤辅助词，不能保证 100% 拦住所有模型措辞；主持备注只写入日志，不再混进公开聊天
- 多人局里如果真人角色有待处理判定，AI 玩家会暂停等待，需要主持人处理后再继续
- 浏览器直连模式（直接双击 `index.html`）没有服务端代理，容易被 CORS 拦截
- 流式输出只覆盖主持叙述；结构化修复、模组导入等仍是整段返回
- 首字出现时间受模型思考阶段影响，通常 3–8 秒，之后逐字显示
- 战斗自动化只覆盖敌方回合；玩家和 AI 玩家的攻击、治疗、移动仍需判定或手动操作
- 多人房间的 AI 托管运行在主持人设备上；主持人关页面后队列停止
- 视角分离是本地界面分离，不是安全权限隔离
- 地图背景图以服务端文件保存，房间状态只保存 URL；当前是矩形裁剪，不包含自由套索裁剪
